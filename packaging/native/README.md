# Apple silicon native helpers

Run `./packaging/native/build_arm64.sh` on an ARM64 Mac with Apple's Command
Line Tools and Boost headers. The default Boost include path is
`/opt/homebrew/include`; override it with `BOOST_INCLUDE_DIR` if needed. The
build used Boost 1.90.0 (`BOOST_VERSION=109000`) and Apple clang 16.0.0. It
targets macOS 11 or newer, uses `-O2` without fast-math, and links only macOS
system libraries. The build script verifies source checksums before compiling.

RapidNJ directly includes Intel's `emmintrin.h` for its sequence distance
calculation. The ARM build's local `include/emmintrin.h` forwards those calls
to the pinned SSE2NEON header. The build retains the upstream source and its
normal optimisations apart from the unsupported `-msse2` flag.

The FastME tag archive contains source files but no generated configure files.
The script supplies the package name/version definitions normally generated by
configure. It also removes a stale `tree *` argument from the two
`SPRTopShift` calls in a temporary copy of `TBR.c`; both the declaration and
definition in the same upstream tag accept three arguments. The archived
source is unchanged. The resulting executable reports `FastME 2.1.5`, as does
the existing Intel executable.

The ARM outputs are `binaries/edmonds-osx-arm64`,
`binaries/fastme-2.1.5-osx-arm64`, and `binaries/rapidnj-osx-arm64`.

On the recorded toolchain, two consecutive builds produced identical Edmonds
and RapidNJ files. FastME's output file has varied bytes between builds, but
the tested 9-taxon Newick result remained identical to the Intel executable.
Thus the build inputs and procedure are pinned; byte-for-byte FastME build
reproducibility has not been established.
