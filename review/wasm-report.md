# PR #118 browser scientific parity review

The browser calculations ran in a Chromium Web Worker. Separately invoked Python candidate calculations supplied the reference. Species fixtures and manifests are under `/private/tmp/grapetree-pr118-review/data`; both Newicks, both matrices, and machine-readable comparison results are retained under `/private/tmp/grapetree-pr118-review/results/wasm-final-float32`.

## Acceptance rule and coverage

Each tree comparison requires identical sample labels and unrooted raw and positive splits, and checks every pairwise path. NJ additionally compares every canonical unrooted branch length, summing degree-two root edges. Its allowance is the theoretical maximum from two independently printed six-significant-digit branch values plus `1e-9` for floating arithmetic. A deliberately misplaced `0.010914` branch fails this check. MSTree, MSTreeV2, RapidNJ and distance matrices retain absolute `1e-5` and relative `1e-6` tolerances. NJ's older pair-path gate of absolute `0.012` and relative `1e-6` remains as a redundant broad check; the per-edge precision gate determines numerical parity. Each matrix comparison checks every labelled cell.

The suite covers Salmonella, Escherichia and Yersinia cgMLST samples of 10 and 50 profiles, plus a synthetic outbreak with duplicates, near ties, missing calls and an outlier. It runs four tree methods on each dataset (28 comparisons), and all four missing-data modes on the 10-profile samples and outbreak (16 full matrices). The permanent browser suite also contains two outbreak regressions, including an NJ per-edge check. The review suite accepts `GRAPETREE_WASM_CASES` JSON `{label,file}` records for independently generated held-back inputs.

## Defects found and corrected

- Standard MSTree initially had different topology on two real 50-profile datasets and the outbreak. It truncated fractional eBurst tie weights before Kruskal selection, enumerated equal-weight edges in a different order, included zero-weight graph edges absent from Python NetworkX, and used JavaScript half-up rather than NumPy half-even rounding. Selection now mirrors the Python graph and its edge order. Those topology and path comparisons then passed.
- Browser NJ omitted a Python postprocessing pass that moves positive branches shorter than `0.1` onto sister branches when a tree has a branch longer than three alleles. Its root placement also differed from ETE's midpoint outgroup and unroot sequence, which made that pass change different sisters. The browser now matches both stages. The outbreak's former `0.010914` misplaced branch is eliminated.
- The browser's symmetric distance matrix retained JavaScript double precision while Python stores each value in NumPy `float32` before handing it to native FastME. This changed a native input after six-decimal serialisation and caused NJ internal-edge differences as large as `0.00006` alleles. Rounding each browser matrix entry once on assignment matches Python. Across the seven original NJ fixtures, the largest branch residual beyond six-significant-digit output rounding fell from `0.00005` to floating arithmetic noise (~`4e-16`). Final NJ Newick serialization also matches ETE's six significant digits.
- An independent held-back Yersinia sample of 137 profiles found one further strict NJ edge failure: Python assigned `0.010026` to ST301 and zero to its ST297 sister, while the browser reversed them. The retained raw FastME tree places numeric index 2 (ST301) before index 1 (ST297). Python's postorder pass first transfers ST301's initial `0.002783125442` onto ST297's `0.007242874558`, then transfers their sum back to ST301 and zeros ST297. The browser's directly joined numeric leaf pair had the reverse child order. The browser now emits those leaf pairs in FastME's descending numeric order. All 40 raw FastME leaf cherries in this sample, and all three in the retained 10-profile native tree, have that order; this evidence does not establish a general order for internal children. The affected held-back case and the original seven NJ cases passed strict edge checks after the change. An eight-profile derived fixture preserves the failure as a permanent regression.

## Evidence and limits

The initial strict run passed **44/44** in 2.5 minutes; the seven NJ cases then passed again after the leaf-order repair. The lead's independent held-back run accepted all **51 unique cases** (42 unaffected cases plus nine NJ cases across six n37/n137 datasets and three fresh n73 samples). A separate ETE parser audited 27 NJ edges and agreed with the custom precision checker. The isolated default browser suite passed **31/31**, including the float32 and leaf-order regressions. A direct replay of the identical saved Yersinia n10 FastME distance matrix succeeded after one transient native run had emitted an empty tree, suggesting native-process instability rather than a deterministic browser discrepancy. The failed input/stat file, successful retry tree, and raw native n137 tree are retained in `results/backend`.

Only Chromium is covered here; Firefox, WebKit and larger browser-memory limits belong to the separate UI review. The browser implements MSTreeV2, MSTree, NJ, RapidNJ and symmetric distance export. Python's blockwise matrix, wgMLST calculation and Ninja are not claimed as browser features.
